# スチャラカトレイン 技術設計

## 全体構成

```
┌─────────────┐     WebSocket      ┌──────────────────────┐
│  ブラウザ     │◄──────────────────►│  CF Workers           │
│  Vite+TS     │                    │  Hono                │
│  Canvas描画   │     POST /api/roll │  Durable Objects     │
└─────────────┘◄────────────────────│  (ゲーム状態管理)      │
                                    │                      │
┌─────────────┐     POST (投稿後)   │  D1                  │
│  mypace      │───────────────────►│  (永続化)             │
│  (Nostr)     │                    └──────────┬───────────┘
└─────────────┘                                │
                                               │ subscribe
┌─────────────┐                                │
│  Nostr       │◄──────────────────────────────┘
│  リレー       │  NPC用: 公開投稿を取得
└─────────────┘
```

## フロントエンド

- **Vite + TypeScript**: ビルド・開発環境
- **Canvas**: マップ・電車・UI描画
- **WebSocket**: サーバーからのリアルタイム更新受信

## バックエンド

- **Hono**: APIフレームワーク（CF Workers上で動作）
- **Cloudflare Workers**: サーバーレス実行環境
- **Durable Objects**: WebSocket接続保持 + ゲーム状態管理（1ルーム = 1 Durable Object）
- **Cloudflare D1**: プレイヤーデータ・物件データ・ゲーム状態の永続化

## プレイヤー認証

- Nostr公開鍵をプレイヤーIDとして使用
- mypaceにログイン済み = 認証済み
- 登録時にNostr公開鍵を紐付ける

## APIエンドポイント（案）

| メソッド | パス | 説明 |
|---|---|---|
| POST | `/api/roll` | サイコロを振る（mypace投稿後に呼ばれる） |
| POST | `/api/action` | 物件購入・カード使用等のアクション |
| GET | `/api/state` | 現在のゲーム状態取得（初期ロード用） |
| WS | `/api/ws` | WebSocket接続（リアルタイム更新） |

## 二重振り防止

- リクエストにNostrイベントID（投稿の一意識別子）を含める
- 同じイベントIDでは2回振れない
- サーバー側でイベントIDの重複チェック

## NPC駆動

- サーバーがNostrリレーにsubscribe
- 公開投稿を受信するたびにNPC1体のサイコロを振る
- NPC物件購入は簡易AI（安い物件を優先、所持金の一定割合以下なら購入）
